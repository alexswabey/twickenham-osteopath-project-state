## LO — Learning Outcomes (summary)

Title: AI Augmented FullStack Bootcamp — HTML/CSS/Bootstrap Individual Project Learning Outcomes and Expected Performance.

There are 5 sections / learning outcomes.

LO1: Learners will be able to design and implement a one-page interactive front-end web application using HTML and CSS based on user experience design principles, accessibility, and responsiveness.

Criterion 1.1 — Front-End Design:
- Design a cohesive one-page layout with a main navigation menu and structured content.
- Ensure the design adheres to accessibility guidelines, including appropriate colour contrast and alt text for non-text elements.
- Use CSS or CSS frameworks such as Bootstrap to create a responsive design.
- Expected performance:
  - Cohesive one-page layout with main navigation menu and structured content.
  - Semantic use of HTML.
  - Adherence to accessibility guidelines, including colour contrast and alt text.
  - No Web Content Accessibility Guideline (WCAG) errors.
  - Layout adapts to different screen sizes using CSS media queries, Flexbox, Grid, and/or Bootstrap without major errors or loss of functionality.

Criterion 1.2 — User Experience:
- Organise information using UX principles so headers convey structure and information is easy to find.
- Ensure the user can initiate and control actions, such as playing media if included, with immediate feedback.
- Expected performance:
  - Information organised using UX principles, including clear headers and prioritised information.
  - User-initiated actions, if chosen, have immediate feedback, for example media control.

LO2: Learners will be able to test and validate the one-page web application through development, implementation, and deployment stages.

Criterion 2.1 — Code Validation:
- Ensure custom HTML and CSS pass W3C and Jigsaw validators with no issues.
- Expected performance:
  - HTML and CSS code passing W3C and Jigsaw validators with no issues.

Criterion 2.2 — Responsive Design:
- Use CSS media queries to ensure the layout is responsive and maintains integrity across different screen sizes.
- Apply semantic markup for HTML to enhance readability and structure.
- Ensure the single page features intuitive navigation.
- Expected performance:
  - Consistent layout across different screen sizes due to CSS media queries.
  - Clear and semantic HTML structure.
  - Intuitive, functional navigation on the single page.

LO3: Learners will be able to deploy the one-page web application to a cloud platform.

Criterion 3.1 — Cloud Deployment:
- Successfully deploy the final version to a cloud-based platform ensuring it matches the development version.
- Use Git and GitHub for version control with a clear commit history and clean, commented code.
- Remove commented-out code before final deployment.
- Ensure all internal links and interactive elements function correctly.
- Expected performance:
  - Successful deployment of the single-page application to a cloud hosting platform with no discrepancies from the development version.
  - Effective use of Git and GitHub for version control with a clear commit history.
  - Removal of commented-out code.
  - Confirmation that all internal links work correctly.

LO4: Learners will be able to maximise future maintainability through documentation, code structure, and organisation.

Criterion 4.1 — Documentation:
- Write a concise README.md file explaining the application's purpose, user value, and deployment procedure.
- Include screenshots of the single-page application with brief descriptions and user value explanations.
- Attribute any code from external sources clearly.
- Expected performance:
  - Concise README.md outlining purpose, user value, and deployment steps.
  - Screenshots and descriptions of features demonstrating functionality and user benefits.
  - Proper attribution of external code sources.

LO5: Learners will be able to leverage AI tools to orchestrate the software development process.

Criterion 5.1 — Use AI tools to assist in code creation:
- Demonstrates strategic use of AI for generating code aligned with project objectives.
- Brief reflection in README.md on key decisions where AI was used to generate code, focusing on outcomes rather than detailed prompts or manual interventions.

Criterion 5.2 — Use AI tools to assist in debugging code:
- Efficient use of AI tools to identify and resolve code issues.
- Brief reflection in README.md summarising AI's role in identifying and resolving bugs, noting key interventions.

Criterion 5.3 — Use AI tools to optimize code for performance and user experience:
- AI-driven optimisation for improved performance and user experience.
- Short reflection on how AI contributed to performance and UX improvements.
- Minimal documentation of AI use.

Criterion 5.4 — Reflect on AI's role in the development process and its impact on workflow:
- High-level reflection on how AI tools affected the development process.
- README.md includes concise insights into how AI influenced workflow, focusing on efficiency and outcomes without in-depth prompt documentation.

## CHK — Submission Checklist (summary)

Title: WAES — Full Stack Bootcamp HTML CSS Bootstrap Project — Submission Checklist.

LO1: Front-End Design & User Experience

Website Design:
- Three-page website, with each page designed to differentiate structure and style.
- Main navigation menu is present and functional.
- Content is structured and organised logically.
- Semantic use of HTML tags, for example header, nav, main, footer.

Accessibility & Visual Design:
- Appropriate colour contrast.
- Alt text for all non-text elements.
- No WCAG errors detected.
- CSS colour variables used for consistent styling.
- WebP images used instead of JPEG/PNG where possible, marked optional.
- Lazy loading applied to images, for example loading="lazy".

Responsive Layout:
- Layout adapts to different screen sizes.
- No major errors or loss of functionality on resize.

User Experience:
- Information organised using UX principles, including clear headers and prioritised information.
- Headers convey structure and hierarchy.
- Information is easy to find.
- User can initiate and control actions, for example play/pause media.
- Immediate feedback provided for user actions, for example submitting a contact form.

LO2: Testing & Validation

Code Validation:
- Custom HTML passes W3C validation.
- Custom CSS passes W3C Jigsaw validation.
- No validation errors or warnings.

Performance Testing:
- Lighthouse performance test completed.
- Accessibility, Best Practices, SEO, and Performance scores reviewed.

LO3: Cloud Deployment:
- Final version deployed to a cloud platform, for example GitHub Pages.
- Deployment matches development version with no discrepancies.
- Git and GitHub used for version control.
- Clear commit history with comments.
- Clean, commented code.
- All commented-out code removed before deployment.
- Internal links and interactive elements function correctly.

LO4: Documentation & Maintainability

README.md requirements:
- Live link to deployed website placed at the top of README.
- Table of contents.
- Website's purpose.
- Brief descriptions of features and user benefits.
- Deployment procedure.
- Screenshots of all pages on both desktop and mobile views.
- Screenshots of passed HTML, CSS, and Lighthouse performance tests.
- Bugs / Errors section.
- Proper attribution for any external code, image, or video sources.
- Declaration of use of AI.
- Optional: colour palette image.
- Optional: wireframes.
- Optional: planned future updates.
